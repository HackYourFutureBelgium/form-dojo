# form-dojo

Repository: `HackYourFutureBelgium/form-dojo` (default branch: `main`).

## Workflow

- Each implementation phase is developed on its own branch (for example `phase-1-starter-site`) and merged to `main` through a pull request.
- Never commit directly to `main` after the initial commit. Do not push unless asked.

## Purpose

A small website where students practice **HTML forms** and **CSS**. The teacher gives students tasks, such as features to add and bugs to fix. Typical tasks:

- Change the color of the text.
- Add a new field to the form with the `name` attribute `xx`.
- Add accessibility to components that lack it (labels, alt text, etc.).

## Claude's role

- Build and maintain the **starter website** students work on.
- Build and maintain the **backend**, the **Dockerfile** and the **deployment pipeline**.
- Do not write the exercises or review student work unless asked. The teacher assigns tasks.

## Student-facing site

- Plain HTML and CSS only. No JavaScript, no frameworks, no build step.
- Files: `index.html` and `styles.css`.
- The form submits (`method="post"`) to the backend endpoint below.
- Keep the code simple and readable. Students must be able to understand every line.

## Backend

- Written in **C#** (ASP.NET Core minimal API). Use the Azure.Data.Tables package for Table Storage.
- The API runs in the same container as the site. It serves `index.html` and `styles.css` as static files and handles the form POST.
- It saves each submission as a row in **Azure Table Storage**.
- Keep it minimal. It should store whatever fields the form sends, so students can add fields without touching the backend.
- Never commit secrets or connection strings. Use environment variables or Container App secrets.

## Hosting and deployment

- Hosted as a single **Azure Container App**. One image contains the site and the API.
- The image lives in **Azure Container Registry (ACR)**.
- A **GitHub Actions** workflow runs on every merge (push) to `main`:
  1. Build the Docker image (multi-stage: .NET SDK image to publish, ASP.NET runtime image to run).
  2. Push it to ACR, tagged with the commit SHA (and `latest`).
  3. Update the Container App to use the new image.
- Authentication from GitHub to Azure uses **OIDC** (federated credential), so no passwords or service principal secrets are stored. Only non-secret IDs (client ID, tenant ID, subscription ID) are kept as GitHub variables or secrets.
- Pull requests may build the image to check it, but must not push or deploy.

## Infrastructure

- **No Terraform or Bicep.** Azure resources are created with **Azure CLI** commands in a single script, `infra/setup.sh`.
- The script is run once by hand and must be safe to re-run (check whether a resource exists before creating it, or use idempotent commands).
- It creates:
  - Resource group
  - Azure Container Registry
  - Storage account (Table Storage)
  - Container Apps environment
  - Container App (the storage connection string is set as a Container App secret and exposed to the app as an environment variable)
  - Federated credential and role assignments so GitHub Actions can push to ACR and update the Container App
- Resource names, location and the GitHub repo are variables at the top of the script.
- Names are based on `form-dojo` (for example `rg-form-dojo`, `ca-form-dojo`). ACR and storage account names allow only lowercase letters and numbers (for example `formdojoacr`), so no hyphens. Storage account names must be globally unique, so add a short suffix if needed.
- The workflow lives in `.github/workflows/deploy.yml`. It is written by hand, not generated by `az containerapp up`.

## Complexity level

Match the HTML/CSS complexity to the HackYourFuture Module-Onboarding issues:
https://github.com/HackYourFutureBelgium/Module-Onboarding/issues

- At the start of each session, read only the issues labeled **week 1** and **week 2** (for example with `gh issue list --repo HackYourFutureBelgium/Module-Onboarding --label "week 1"`).
- Use them to decide which elements and CSS properties are in scope. Do not use concepts beyond those issues.
